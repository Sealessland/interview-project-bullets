# Contributing

Thanks for improving Interview Project Bullets.

## Before opening a change

- Keep guidance grounded in observable project evidence.
- Do not add rules that encourage invented metrics, ownership, users, or production impact.
- Keep the core workflow concise; put mode-specific detail in `references/`.
- Run the skill validator before submitting.

```bash
python3 ~/.codex/skills/.system/skill-creator/scripts/quick_validate.py .
```

## Pull requests

Explain the user problem, the behavior that changes, and how the change was validated. Documentation changes should include a realistic example or explain which ambiguity they resolve.
